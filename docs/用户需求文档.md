## 1. 产品概述

### 1.1 一句话定位
一个轻量的每日饮食记录网页：**10 秒记一餐，AI 帮你想吃啥，日历帮你回看每一顿**。

### 1.2 背景与问题
- 想记录饮食的人很多，但主流工具（如薄荷健康等）功能重、操作路径长、广告与营销多，"记一餐"的心理成本高，导致三天放弃。
- 用户真正高频的需求只有三件：**快速记下今天吃了什么、纠结时有人（AI）给个答案、过段时间翻回去看看**。
- 因此本产品把"记录成本"压到极限（手动 10 秒 / 随机一键 / 对话式），把"回看"做成有成就感的打卡印章墙。

### 1.3 产品目标
1. 记录一餐的全程操作 ≤ 15 秒。
2. 三种记录入口（手动 / 随机推荐一键记录 / AI 食谱一键记录）覆盖"我知道吃了啥"与"我不知道吃啥"两类场景。
3. 所有记录按登录用户持久化存储，可随时按日回看。

### 1.4 成功指标（上线后 3 个月）
| 指标 | 目标 |
| --- | --- |
| 次日留存 | ≥ 30% |
| 单次记录耗时 | ≤ 15s |
| 周活用户人均记录 | ≥ 10 餐/周 |
| 随机推荐 → 一键记录转化 | ≥ 25% |

## 2. 目标用户与使用场景

### 2.1 用户画像
| 画像 | 特征 | 核心诉求 |
| --- | --- | --- |
| A · 减脂期上班族（25–35 岁） | 关注总热量，午晚饭后顺手记 | 快速记 + 知道今天还剩多少额度 |
| B · 健身增肌人群 | 关注蛋白质摄入 | 营养素统计、高蛋白推荐 |
| C · 生活记录爱好者 | 不严格控制，只想"留痕" | 日历回看"那天吃了啥"、打卡成就感 |

### 2.2 关键场景
1. **早晨纠结**：打开"来一餐"，一键随机抽一个，抽到就吃，顺手记录。
2. **冰箱剩食材**：打开"问 AI"："有鸡蛋、番茄、米饭，10 分钟能做什么？"→ 得到食谱 → 一键记录。
3. **饭后 10 秒**：主页点「+」→ 选餐次 → 输名字和分量 → 保存。
4. **周末回看**：打开日历，印章密集=这周好好吃饭了；点任意日期查看当天明细。

## 3. 功能需求

优先级：P0 = 首版必须；P1 = 首版尽量；P2 = 后续迭代。

### 3.1 用户系统（P0）
| 需求点 | 说明 |
| --- | --- |
| 注册 | 用户名或邮箱 + 密码（≥ 8 位，含字母数字）；重复用户名/邮箱给出明确报错 |
| 登录 | 支持用户名或邮箱登录；密码错误提示"邮箱或密码不正确"，不泄露具体哪个错 |
| 会话保持 | 登录态持久（7–30 天），刷新/重开浏览器无需重新登录 |
| 退出登录 | 设置/我的页面提供退出入口 |
| 数据隔离 | 一切业务数据按用户隔离，仅本人可读写（行级权限） |

### 3.2 今日记录 · 主页（P0）
- 顶部：日期与问候语、连续打卡天数徽章。
- **今日摄入票据卡**：摄入总热量（大数字）/ 目标热量、剩余额度环形图、蛋白质/碳水/脂肪三条进度。
- 三大快捷入口：记一餐（手动）、来一餐（随机）、问 AI。
- 按餐次分组（早餐/午餐/晚餐/加餐）展示记录列表：食物名、份量、时间、热量。
- 单条支持编辑与删除（删除需二次确认）。
- **空态**：某餐无记录时显示虚线占位卡 + 引导文案（"还没安排 · 去来一餐抽一个"）。
- 首次使用空态：全空页面给出"记下第一餐"主按钮引导。

### 3.3 手动录入 · 记一餐（P0）
- 字段：食物名称（必填）、餐次（默认按当前时间推断）、份数 + 单位（个/碗/杯/克/份）、热量 kcal（可空）、日期（默认今天，允许补记过去 7 天）、备注（可选）。
- **热量可留空**：留空时提供「AI 估算」按钮，按食物名与分量估算热量并回填（用户可改）。
- 常吃食物快捷条：一键回填名称与默认分量（如鸡蛋、牛奶、燕麦、美式、全麦面包、鸡胸肉）。
- 校验：名称必填；热量 0–5000；份数 0.1–50。错误就地提示，不弹窗。
- 保存后返回主页，列表与汇总**乐观更新**，并给轻提示"已记到午餐"。

### 3.4 随机推荐 · 来一餐（P0）
- 主视觉："今天吃什么？" + 大按钮「抽一下」。
- 抽取结果为一张菜品卡：名称、预估热量、烹饪时长、标签（家常/低卡/高蛋白/快手/素食…）。
- 操作：「换一个」继续抽（带翻卡动画）；「记录这一餐」一键写入**今日对应餐次**（按当前时间推断，可在录入页改）。
- 筛选标签：不限 / 低卡 / 高蛋白 / 素食 / 10 分钟快手；筛选影响抽取池。
- 数据源：内置约 100 道家常菜种子库；P1 起结合用户饮食偏好过滤（素食者不抽到荤菜）。

### 3.5 AI 问答食谱 · 问 AI（P0）
- 对话式交互：输入"现有食材 + 时长 + 目标（低卡/高蛋白）"，AI 返回**结构化食谱卡**（菜名、食材清单、步骤、预估热量）。
- 支持**流式输出**（打字机效果），超时 20s 或失败时给出兜底文案与"重试"。
- 食谱卡上的操作：「记录这餐」一键写入今日记录；「收藏食谱」存入我的收藏（P1）。
- 支持多轮追问（"换成素食做法""热量再低一点"）。
- 内置快捷提问 chips，降低冷启动门槛。
- 合规：AI 回复附"热量为估算值，仅供参考"。

### 3.6 日历视图 · 历史记录（P0）
- 月历视图：有记录的日期显示打卡圆点，今天高亮，可左右切换月份。
- 选中任意日期 → 下方展示该日汇总（总热量、各餐明细，只读）。
- 月度统计条：本月记录天数、连续打卡天数、日均热量。
- 无记录日期：明细区显示空态"这一天没有留下记录"。

### 3.7 个人设置 · 我的（P1）
- 昵称、头像（可选）、每日热量目标（默认 1800 kcal，提供按身高/体重/目标的一键估算）。
- 饮食偏好：素食/忌口标签，影响随机推荐与 AI 回答。
- 常吃食物管理、退出登录。

### 3.8 其他（P1/P2）
| 优先级 | 功能 |
| --- | --- |
| P1 | 收藏食谱；记录导出 CSV；补记提醒 |
| P2 | 微信登录；小程序端；体重记录；拍照识别食物 |

## 4. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 首屏可交互 < 2s；保存记录本地即时反馈（乐观更新）；AI 首字输出 < 3s |
| 安全 | 密码由认证服务加密存储，明文不出现在任何日志；业务数据行级权限仅本人可见；前端不落任何密钥 |
| 可用性 | 移动端优先（≥ 360px 宽全适配）；键盘可达、焦点可见；遵循 `prefers-reduced-motion` |
| 可靠性 | 网络失败时录入表单保留草稿；AI 失败可重试；删除操作二次确认 |
| 兼容 | Chrome / Edge / Safari / 微信内置浏览器近两年主版本 |

## 5. 信息架构与关键流程

### 5.1 站点结构
```
未登录 ──► 登录 / 注册
                 │
                 ▼
┌─────────── 底部 Tab ───────────┐
│  今日   来一餐   [+]   问AI   日历  │
└────────────────────────────────┘
   今日 ──[+]──► 记一餐（表单弹层）
   来一餐 ──► 抽卡 ──「记录这一餐」──► 写入今日
   问AI ──► 对话/食谱卡 ──「记录这餐」──► 写入今日
   日历 ──► 选中日期 ──► 当日明细（只读）
   我的（P1）
```

### 5.2 关键流程
1. **注册登录**：填表 → 校验 → 注册成功自动登录 → 进入今日主页（空态引导）。
2. **手动记录**：今日 →「+」→ 填写（可 AI 估算热量）→ 保存 → 主页汇总与列表更新。
3. **随机 → 记录**：来一餐 → 抽一下 →（换一个 /）记录这一餐 → 自动按当前时段写入餐次 → 轻提示成功。
4. **AI → 记录**：问 AI → 提问 → 流式食谱卡 → 记录这餐 → 写入今日记录。
5. **回看**：日历 → 切月/选日 → 当日明细。

## 7. 数据模型

> 采用 CloudBase 文档型数据库（若最终环境为 PG 模式，则等价映射为表 + 行级安全 RLS）。用户身份由认证服务托管，不自建用户表，仅存扩展档案。

### 7.1 profiles（用户档案）
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| userId | string | 与认证 UID 一致，唯一 |
| nickname | string | 昵称，默认取用户名 |
| dailyTargetKcal | number | 每日热量目标，默认 1800 |
| dietTags | string[] | 饮食偏好（vegetarian / noBeef …） |
| createdAt | date | 创建时间 |

### 7.2 food_records（食物记录）
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| _id | string | 自动 |
| userId | string | 所属用户 |
| date | string | 记录日 `YYYY-MM-DD`（按本地时区） |
| mealType | string | `breakfast / lunch / dinner / snack` |
| name | string | 食物名 |
| qty | number / unit | 份数与单位（个/碗/杯/克/份） |
| kcal | number | 热量，0 表示未填（估算中） |
| protein / carb / fat | number? | 可选营养素（g） |
| note | string? | 备注 |
| source | string | `manual / random / ai` 记录来源 |
| createdAt / updatedAt | date | 时间戳 |

索引：`(userId + date)` 复合索引、`(userId + mealType)`。
权限：仅 `userId` 本人可读写。

### 7.3 dishes（推荐菜库）
`_id, name, kcal, minutes, tags[], ingredients[], steps[], coverColor`，全局只读种子数据约 100 条；P1 支持收藏食谱并入。

### 7.4 ai_chats（P2，对话留存）
`_id, userId, role(user/assistant), content, recipeRef?, createdAt`。

## 8. 技术方案建议

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 前端 | Vite + React + TypeScript | 响应式；移动端优先断点 |

## 9. 设计规范（原型遵循）

- **美学方向**：Organic/natural · 市集手账风——菜市场小票、印章打卡、营养标签排版。
- **配色**：纸面米白 `#FFF8EE`（背景）/ 墨炭 `#2B2520`（文字线条）/ 番茄红 `#E8502F`（主色 CTA）/ 蔬菜绿 `#3E8E4E`（辅助成功）/ 蛋黄 `#F4B63F`（高亮标签）/ 可可深棕 `#31261B`（AI 面板等深色块）。
- **字体**：Display「ZCOOL KuaiLe」（logo/大标语，克制使用）；Body「Noto Sans SC」；数据「DM Mono」（热量、编号、日期）。
- **签名元素**：① 每条食物记录渲染为"饮食小票"行卡（虚线撕边 + 等宽数字）；② 日历打卡为"印章圈"；③ 今日摄入为微倾斜"营养标签票据卡"（硬阴影、粗规则线）。
- **图标**：统一使用 FontAwesome 6，禁止 emoji 作图标。
- **动效**：抽卡翻转、保存轻提示、打卡点出现动画；整体克制，尊重 reduced-motion。

## 10. 里程碑建议

| 里程碑 | 内容 | 预估 |
| --- | --- | --- |
| M1 | 项目骨架 + 认证（注册/登录/会话） | 1 人日 |
| M2 | 手动录入 + 今日主页（CRUD、汇总） | 2 人日 |
| M3 | 日历视图与历史明细 | 1 人日 |
| M4 | 随机推荐 + 菜库种子数据 | 1 人日 |
| M5 | AI 问答食谱（流式、一键记录） | 1.5 人日 |
| M6 | 设置页、联调、部署上线 | 1 人日 |

### 验收标准（摘要）
- 未登录访问任何业务页 → 跳转登录；登录态刷新不丢失。
- 手动记录保存后，主页汇总与日历打卡即时可见；刷新后数据仍在（数据库持久化）。
- 记录仅本人可见（换账号登录看不到他人记录）。
- 随机推荐"记录这一餐"→ 今日列表出现该菜品，来源标记 `random`。
- AI 提问返回含食材/步骤/热量的食谱卡，"记录这餐"可落库。
- 移动端 375px 宽下无横向滚动、无遮挡。
